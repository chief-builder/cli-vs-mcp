The Token Boundary

The controller creates and verifies private repositories. The agent is meant to receive only the narrower per-arm credential.

In this run, inherited GH_/GITHUB_ variables are removed, each arm gets a positive --tools list, file tools are denied under ~ and the repo, the skill arm's Bash runs inside Claude Code's OS sandbox (keychain and $HOME blocked), and each trial gets an empty GH_CONFIG_DIR. Tier 1 used a read-only agent token (Contents, Issues, PRs, and Actions read); Tier 2 used a separate read-write one with no admin. All tokens are owned by the same GitHub user. The first run didn't hold this boundary; see the first-run note.

Where Success Misleads

Two GitHub task groups have the same shape: the skill arm produces the right end state, but every trial uses shell behavior outside the intended gh surface.

Route shape: CLI can reach the result while leaving the boundary; the MCP route goes through typed tool calls.

Skill taskRaw successValid surfaceEscape pattern
repo_inventory5/50/5gh api … | base64 -d in all five trials.
file_patch_pr5/50/5base64 -d on read, plus shell variable assignment and $(…) command substitution to build the PUT body.

For repo_inventory and file_patch_pr the pattern is not random. When gh lacks a high-level workflow primitive, the agent glues raw API calls together with shell text. That can be effective, but it is no longer the intended CLI-only surface.

Prompting The Skill Back Into Surface

A directed prompt for file_patch_pr named the in-surface workaround: write request bodies to files, then pass them to gh api --input. More trials stayed in surface, but none of those finished, and no trial both passed and stayed valid.

Passing directed trials averaged 401,861 tokens, 2.63x the original 153,022, and both were invalid.

What improved

Validity: three of five trials stayed in surface, up from none with the original prompt.

What did not

The three valid trials all timed out at 240 s after 10–13 turns; their transcripts end in extended thinking with no further tool calls. The two passing trials both escaped, one with $(…) in gh pr create and one with base64 -d. No trial both passed and stayed in surface.

Takeaway

GitHub shows why success rate needs a validity check. CLI skill fails containment when the CLI lacks the workflow primitive, and prompting it back into surface cost it the passes. MCP was clean on every task and cheaper on every clean comparison, 1.52x–1.77x. Success rate alone hides the containment failures.
