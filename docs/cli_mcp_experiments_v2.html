CLI skill or MCP server: choose by primitive fit, not familiarity.

The same agent, prompt, model, and task can behave very differently depending on whether it reaches through a CLI skill or a typed MCP server.

Run n5-v2, October 2026: Claude Code 2.1.288, claude-sonnet-4-6, pinned subjects (@playwright/cli 0.1.13, @playwright/mcp 0.0.75, github-mcp-server v1.0.4). N=5 per task for skill and MCP, N=2 for baseline; 161 trials. Two domains: Playwright and GitHub. Exact numbers come from the checked-in run artifacts; visuals here are explanatory anchors, not data sources.

The Experiment In One Screen

Every trial changes one thing: the tool surface. The task, seed, prompt, model, and wall-clock budget stay fixed. The harness then scores both the end state and whether the agent stayed inside the surface it was supposed to use.

baseline
No browser, no GitHub. Reasoning floor.
skill
Skill docs plus Bash for gh or playwright-cli.
mcp
Structured server tools over stdio. No Bash.

How isolation works in this run: each arm gets a positive --tools list; file tools are denied under ~ and the repo; the GitHub skill arm's Bash runs inside Claude Code's OS sandbox (keychain and $HOME blocked); each trial gets an empty GH_CONFIG_DIR, and inherited GH_/GITHUB_ variables are removed. GitHub Tier 1 uses a read-only agent token, Tier 2 a separate read-write one (no admin); both are owned by the same GitHub user. The first run had looser isolation; see First run (May 2026).

Finding 1: When Primitives Match, MCP Costs Less

In the clean comparisons where both arms passed and stayed valid, MCP used fewer tokens on every task in both experiments: skill/MCP was 1.5x-2.1x everywhere except Playwright form at 2.67x. Turn counts are within about 3 on the GitHub tasks but not on all Playwright tasks: form took 18.8 skill vs 13.6 MCP turns, products 17.4 vs 21.4. How To Choose

The practical rule: pick the surface whose primitives already match the workflow. If neither does, expect shell escapes on the CLI side, and measure both before standardizing.

Pick or build a CLI skill when

The workflow is already a CLI command. Examples: gh issue create, gh pr diff. The agent does not need shell glue.
Humans need the same surface. A CLI is operationally useful outside agent runtimes.
Some extra token cost is acceptable. In this run's clean tasks, skill cost 1.5x-2.1x MCP, 2.67x on the Playwright form task. The multiple depends on the harness setup; the direction held in both runs.

Pick or build MCP when

The workflow needs typed primitives. Examples: create branch, update file, open PR as separate named tools.
Containment matters. No shell means no pipes, env probes, command substitution, or local text plumbing.
Agents will run this at volume. Lower token cost per task adds up when workflows repeat often.
If both fit MCP was cheaper on every clean task in both runs.
If CLI lacks a primitive Expect shell glue and validate the surface.
If MCP lacks a primitive Check the server's tool catalog first; this study has no recorded case that sizes the cost.
If the stakes are high Run both on seeded tasks before committing.

First Run (May 2026)

The first full run, n5, is kept as history. Its numbers differ from the ones above, and the reasons are worth keeping next to them.

What n5 showed, and why it differs

  • Setup: Claude Code 2.1.142–2.1.143 with looser isolation. --allowed-tools did not restrict tools, and the runner's env scrub didn't apply. The results have been re-classified with the current classifier.
  • issue_triage was invalid: the agent token was mis-scoped and lacked Issues read, and the skill arm's passes used escalated credentials.
  • Figures: Playwright Tier 1 1.64x and Tier 2 1.86x skill/MCP (1.52x on completed trials); Playwright clean tasks 1.29x–1.42x, form 2.51x; MCP tier2_recovery 2/5; GitHub clean tasks 1.13x–1.38x; directed prompt 1/5 pass and valid.
  • Why the ratios rose in n5-v2 (an observation, not a proven cause): MCP got cheaper by more than skill did (e.g. pr_diff_answer MCP 55,534 → 38,840 tokens, skill 73,146 → 66,564). At the same time the fixed first-turn context per arm shrank: MCP ~12.3k → ~8.3k (Playwright) and ~8.8k (GitHub), skill ~16.6k → ~13.0k and ~15.1k, baseline ~12.1k → ~9.6k. The skill arm keeps a larger fixed context, the loaded skill text.
  • Two things changed together: the tool restriction (--tools, from ~22–24 built-in tools to 2–5) and the Claude Code upgrade from 2.1.143 to 2.1.288. This run can't separate them. The multiple depends on the harness setup; the direction (MCP cheaper) held in both runs.
