CLI skill or MCP server: choose by primitive fit, not familiarity.

The same agent, prompt, model, and task can behave very differently depending on whether it reaches through a CLI skill or a typed MCP server.

N=5 per task. Two domains: Playwright and GitHub. Exact numbers come from the checked-in run artifacts; visuals here are explanatory anchors, not data sources.

Token ratio 1.13x-1.42x MCP is usually cheaper when both surfaces expose the task primitive cleanly.
15/25 GitHub skill trials succeeded by stepping outside the intended gh-only surface.

Finding 3: Missing MCP Primitives Burn Budget

MCP fails differently. It cannot fall back to shell helpers, so when the needed tool is missing or hard to discover, the agent fans out across adjacent tools.

How To Choose

The practical rule: pick the surface whose primitives already match the workflow. If neither does, expect either shell escapes or MCP fanout and measure before standardizing.

Pick or build a CLI skill when

The workflow is already a CLI command. Examples: gh issue create, gh pr diff. The agent does not need shell glue.
Humans need the same surface. A CLI is operationally useful outside agent runtimes.
Some extra token cost is acceptable. In clean tasks, skill often costs about 1.1x-1.4x MCP, with bigger gaps on chatty workflows.

Pick or build MCP when

The workflow needs typed primitives. Examples: create branch, update file, open PR as separate named tools.
Containment matters. No shell means no pipes, env probes, command substitution, or local text plumbing.
Agents will run this at volume. Lower per-turn payload becomes meaningful when workflows repeat often.
If both fit MCP is usually cheaper.
If CLI lacks a primitive Expect shell glue and validate the surface.
If MCP lacks a primitive Expect fanout and timeouts.
If the stakes are high Run both on seeded tasks before committing.
