The Cost Picture

Both browser surfaces completed every task cleanly, and MCP was cheaper on every one, 1.53x–2.07x. The form task is the outlier at 2.67x: the skill arm fills one field per fill call, while MCP fills the whole form with one batched browser_fill_form.

Why The Form Task Costs More

The data doesn't support a general mechanism, and the skill arm did not snapshot after every action. On tier1_form it made 25 fill calls but only 8 snapshot calls across five trials; MCP made 10 browser_snapshot calls. The form gap comes from per-field fill calls versus one batched browser_fill_form.

Skill form fill

  1. playwright-cli fill for one field
  2. Repeat for each remaining field
  3. 25 fill calls over five trials
  4. Only 8 snapshot calls over five trials

MCP form fill

  1. browser_fill_form with every field
  2. One batched call per trial
  3. 10 browser_snapshot calls over five trials

Recovery Now Converges

Lower cost and convergence went together in this run. On tier2_recovery, the first run's weak spot for MCP, both arms passed 5/5 and stayed in surface.

Conservative read: MCP solved the recovery flow in all five trials, averaging 115,117 tokens and 16.2 turns against the skill arm's 236,852 tokens and 20.6 turns (2.06x). The first-run result for this task is in the first-run note.

Takeaway

For browser automation, MCP was cheaper on every Playwright task, with the same 5/5 success on all six, recovery included. The multiple depends on the harness setup, 1.53x–2.07x here with form at 2.67x; the direction (MCP cheaper) held in both runs. Success and cost still have to be read together.
